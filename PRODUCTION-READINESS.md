# Production readiness

Reviewed 19 November 2026. This file separates what is done and tested from what is done but untested, and from what does not exist yet. It does not overstate: where something was not run, it says so.

## 1. What the app is today

A **client-side Next.js application**. All logic runs in the visitor’s browser. The server only renders the HTML shell and serves static files. There is:

- **No backend API** (no route handlers, no server actions)
- **No database** (state lives in the visitor’s browser `localStorage`)
- **No authentication** (anyone with the URL sees the Chai Social workspace)
- **No third-party API calls** (Square, Google, Deliveroo, Uber Eats, Just Eat, OpenTable, Tripadvisor, Met Office and Instagram/Facebook are shown as connectors but are simulated)
- **No calls to Anthropic, Claude or any AI service.** Campaign copy and Ask Calon answers are generated by templates from the engine’s numbers.

It is self-contained: `npm ci && npm run build && npm start` is all it needs.

## 4. Security review

- **No secrets in the code.** No API keys, tokens or passwords anywhere; `.env*` is git-ignored.
- **No user input reaches a server.** Text typed into campaign editors and profile fields stays in the visitor’s browser.
- **One inline script** (`src/app/layout.tsx`) clears stale caches and old service workers. It contains no user data. `dangerouslySetInnerHTML` is used only for this fixed string.
- **Headers added:** `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options: DENY`, `Permissions-Policy`, `Strict-Transport-Security` (1 year), `X-Powered-By` removed.
- **Not yet:** a Content-Security-Policy. Next.js inline scripts need a nonce via middleware; add it when you add auth.
- **HTML is never cached** (`no-store` on documents) so a deploy is seen at once; hashed assets keep Next’s long cache.
- **Clipboard** is used only on a button tap (reply drafts).

## 5. Deployment risks to know about

1. **Public URL = public demo.** Without auth, anyone with the link sees Chai Social’s simulated workspace. Use a Vercel preview with password protection, or add auth, before sharing widely.
2. **Chai Social is a real restaurant.** The demo shows simulated takings and reviews under its name. The header says “Demo data”; keep that label, and have the owner’s written agreement before launching publicly.
3. **Named competitors on Home** (Mint Leaf and others) carry invented scores from the original build. Replace them with anonymous labels if any name matches a real Cardiff business.
4. **Unverified prices** (thali, chai, naan, drinks) are marked in `src/engine/workspaces/chai-social.ts`.
5. **Time zone:** the engine uses the visitor’s local time. Correct for UK visitors; a viewer abroad sees “today” in their own zone.
6. **`force-dynamic`** renders the shell on every request. Fine on Vercel; if you want a fully static export later, remove it and the per-request header logic.
7. **Fonts** are downloaded from Google at build time; a build without internet access fails.
